# 短时创作技术选型

本页是技术路线决策表，不指定作品题目。先按比赛工作站已安装环境和允许服务选技术，再决定玩法。

## 1. 选择矩阵

| 想做的体验 | 最轻路线 | 更复杂时 | 主要风险/兜底 |
|---|---|---|---|
| 一屏互动页面、可视化、点击/拖拽 | HTML/CSS/JavaScript + Canvas/SVG | p5.js用于生成式图形 | 少依赖；先定义输入事件和状态机。没有网络时可用本地静态页面 |
| 2D游戏有场景/碰撞/关卡 | Phaser | 自写Canvas仅适合单画面简单玩法 | Phaser要熟悉Scenes/Assets/Physics；先做一关。素材许可另核 |
| 摄像头手势/姿态互动 | 浏览器`getUserMedia` + MediaPipe Tasks Vision，在设备本地识别 | TensorFlow.js Pose等 | 摄像头权限、HTTPS/localhost、模型下载、浏览器和GPU兼容；鼠标/键盘模拟传感器结果 |
| 语音交互 | Web Speech API或比赛批准的本地/云语音服务 | 语音识别 + LLM + TTS流水线 | 浏览器/语言支持、网络、噪声和许可；手动文本输入回退 |
| 生成内容或Agent工具调用 | 比赛批准的Agent平台/API；Agent输出结构化JSON | 多Agent分工 | 不让LLM逐帧/每点击调用；限制输出Schema、超时、Token预算和默认数据 |
| 小程序/云后端 | 只在比赛环境提供且获准的平台能力 | 实时数据库/云函数 | 云账号、权限、部署时间、网络；本地Mock保持演示可运行 |

## 2. 视觉输入的通用数据流

`Camera → on-device vision task → {label, confidence, coordinates, timestamp} → application state machine → UI/score`

- 输入适配器只输出最小结构化事件，不让核心游戏绑死在特定SDK上。
- `confidence`不足、手/人离开画面或模型未加载时要显示状态，不能默默判定失败。
- 第一个可玩版用键盘/点击生成相同事件；摄像头接入是一个替换输入源，而不是阻塞主循环的前置条件。
- 用户拒绝摄像头许可时照样能体验；明确告知本地处理情况，不上传原始帧。
- Agent只在玩家开始/完成回合时拿到必要的非敏感字段（主题选择、得分、难度），按Schema生成下一轮；校验后才进入游戏。

## 3. 先选可运行而不是“最炫”

1. 查看赛事电脑环境：浏览器、Node/Python版本、摄像头、GPU、依赖代理、网络、模型预装和API权限。
2. 盘点比赛要求和远程操作边界；工具只用主办方批准的GPT-Station/KCoder/连接器。
3. 空白项目启动页先跑通，确认Run/Preview/部署入口后再增加SDK。
4. 用假的手势/输入跑通完整主链路，再接真实传感器/模型。
5. 固定依赖版本，README记录安装/启动/测试；离线准备Mock数据与备用素材。
6. 主线失效时切回鼠标/键盘交互、默认关卡和内置文案；不要临近封板临时更换框架。

## 4. Agent效率与产品质量

- 传感器算法在本地连续运行，游戏状态更新不依赖Agent响应；Agent只处理低频、可复核的文本或配置任务。
- 使用固定枚举、长度限制、数值边界和白名单校验Agent输出；失败时用静态配置。
- 每个Agent工单写清文件范围、接口、验收、停止条件；实际修改后运行命令和浏览器验收并记录证据。
- 夜间任务先确保目标在线、额度、权限、告警和停止时间；保存了工作流不等于任务成功执行。

## 5. 不在比赛开始后才发现的兼容问题

- 摄像头API通常要求安全上下文（localhost或HTTPS）；比赛预览地址和屏幕录制要提前验证权限。
- CDN/npm模型下载可能被网络策略阻挡或耗时；提前确认是否允许缓存/本地模型，未经批准不要绕过网络或远程操作限制。
- Mac/Windows浏览器的摄像头权限、分辨率和方向不同；给动作阈值留校准方式。
- 连接器/桌面客户端关闭后，Agent或定时会话不保证仍在执行；离场前核验状态，返场后复查输出。
- 各开源仓库README的命令不代表比赛机上实际通过；现场独立执行并记录测试状态。
