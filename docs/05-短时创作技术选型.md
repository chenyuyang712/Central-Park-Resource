# 短时创作技术选型

本页是技术路线决策表，不指定作品题目。先按比赛工作站已安装环境和允许服务选技术，再决定玩法。

## 1. 选择矩阵

| 想做的体验 | 最轻路线 | 更复杂时 | 主要风险/兜底 |
|---|---|---|---|
| 一屏互动页面、可视化、点击/拖拽 | HTML/CSS/JavaScript + Canvas/SVG | p5.js用于生成式图形 | 少依赖；先定义输入事件和状态机。没有网络时可用本地静态页面 |
| 2D游戏有场景/碰撞/关卡 | Phaser | 自写Canvas仅适合单画面简单玩法 | Phaser要熟悉Scenes/Assets/Physics；先做一关。素材许可另核 |
| 摄像头手势/姿态互动 | 浏览器`getUserMedia` + MediaPipe Tasks Vision，在设备本地识别 | TensorFlow.js Pose等 | 摄像头权限、HTTPS/localhost、模型下载、浏览器和GPU兼容；鼠标/键盘模拟传感器结果 |
| 语音交互 | Web Speech API或比赛批准的本地/云语音服务 | 语音识别 + LLM + TTS流水线 | 浏览器/语言支持、网络、噪声和许可；手动文本输入回退 |
| 生成内容或Agent工具调用 | 比赛批准的Agent平台/API；Agent输出结构化JSON | 多Agent分工 | 不让LLM逐帧/每点击调用；限制输出Schema、超时、Token预算和默认数据 |
| 小程序/云后端 | 只在比赛环境提供且获准的平台能力 | 实时数据库/云函数 | 云账号、权限、部署时间、网络；本地Mock保持演示可运行 |

## 2. 视觉输入的通用数据流

`Camera → on-device vision task → {label, confidence, coordinates, timestamp} → application state machine → UI/score`

- 输入适配器只输出最小结构化事件，不让核心游戏绑死在特定SDK上。
- `confidence`不足、手/人离开画面或模型未加载时要显示状态，不能默默判定失败。
- 第一个可玩版用键盘/点击生成相同事件；摄像头接入是一个替换输入源，而不是阻塞主循环的前置条件。
- 用户拒绝摄像头许可时照样能体验；明确告知本地处理情况，不上传原始帧。
- Agent只在玩家开始/完成回合时拿到必要的非敏感字段（主题选择、得分、难度），按Schema生成下一轮；校验后才进入游戏。

## 3. 先选可运行而不是“最炫”

1. 查看赛事电脑环境：浏览器、Node/Python版本、摄像头、GPU、依赖代理、网络、模型预装和API权限。
2. 盘点比赛要求和远程操作边界；工具只用主办方批准的GPT-Station/KCoder/连接器。
3. 空白项目启动页先跑通，确认Run/Preview/部署入口后再增加SDK。
4. 用假的手势/输入跑通完整主链路，再接真实传感器/模型。
5. 固定依赖版本，README记录安装/启动/测试；离线准备Mock数据与备用素材。
6. 主线失效时切回鼠标/键盘交互、默认关卡和内置文案；不要临近封板临时更换框架。

## 4. Agent效率与产品质量

- 传感器算法在本地连续运行，游戏状态更新不依赖Agent响应；Agent只处理低频、可复核的文本或配置任务。
- 使用固定枚举、长度限制、数值边界和白名单校验Agent输出；失败时用静态配置。
- 每个Agent工单写清文件范围、接口、验收、停止条件；实际修改后运行命令和浏览器验收并记录证据。
- 夜间任务先确保目标在线、额度、权限、告警和停止时间；保存了工作流不等于任务成功执行。

## 5. 不在比赛开始后才发现的兼容问题

- 摄像头API通常要求安全上下文（localhost或HTTPS）；比赛预览地址和屏幕录制要提前验证权限。
- CDN/npm模型下载可能被网络策略阻挡或耗时；提前确认是否允许缓存/本地模型，未经批准不要绕过网络或远程操作限制。
- Mac/Windows浏览器的摄像头权限、分辨率和方向不同；给动作阈值留校准方式。
- 连接器/桌面客户端关闭后，Agent或定时会话不保证仍在执行；离场前核验状态，返场后复查输出。
- 各开源仓库README的命令不代表比赛机上实际通过；现场独立执行并记录测试状态。

## 6. 从创意赛案例选一个短赛技术闭环

| 玩法信号 | 案例启发 | 24小时MVP建议 | 主要取舍 |
|---|---|---|---|
| AI辅助音乐学习/听觉训练 | 腾讯音乐Hackathon获奖名单含Melo；官方页未公开代码 | 先做一个音程/节奏练习、即时答案反馈与一段自适应解释；音乐交互不必依赖复杂生成音频 | 先核实赛事模型与音频版权；播放可用程序音/自录授权素材 |
| AI进入游戏核心玩法 | 腾讯游戏创作大赛AI赛道要求AI参与核心玩法；2025获奖项目包括《觉醒AI》《Aivilization》《遥远行星建造师》《我的恋综超失控！》等 | 做一个明确的状态机/事件，AI只在关键行动后影响一个可观察变量；控制一次调用并备静态事件 | 玩法要可玩；AI输出不应直接控制未校验的胜负或分数 |
| AI角色/社交 | 小红书作者自述《喵呜岛》猫角色观察玩家、相互传播八卦；其反馈称AI聊天变慢后重做架构 | 先用2–3个有固定记忆槽/关系值的NPC，限制对话长度与调用频率，用预设摘要让NPC关系可演示 | 该案例是作者自述、源码未核验；全量实时自由聊天易产生延迟/成本和剧情不稳定 |
| 文字冒险/收集 + AI总结 | [《寻踪》公开仓库](https://github.com/cozease/tencent-hackathon)，获奖为README作者自述，MIT代码 | 首选：确定性选择/事件/图鉴 → 结算时生成一次个性化回顾；无模型时预设回顾仍可完整通关 | 实际仓库使用OpenAI-compatible后端，训练营须以批准的模型配置替换；版权/资源需逐项核验 |
| 文本编辑音频/AR试穿 | 字节跳动《简音》《道具OMG》赛后访谈 | 借鉴“把专业流程变简单”，可先做文本段落删改与时间线模拟；AR/3D则先拿一个固定样品做端到端验证 | 访谈无源码；相机标定/语音克隆等高风险功能先做小样和兜底 |

### 推荐的通用系统切分

`可预测的游戏/编辑状态机 → 明确记录事件 → Agent只在关键节点生成一个受限结果 → Schema校验 → 展示 / 静态回退`

先交付一个不依赖模型也能从开始走到结果的闭环，再把AI加到有明确用户价值的步骤。遇到响应慢，优先压缩上下文、把调用移到回合结算、显示非阻塞等待和提供默认内容；不要让摄像头每帧、每次按键或NPC每句对话都产生一次模型调用。

## 7. 平台型VibeCoding获奖作品的MVP模式

| 获奖案例 | 核心体验 | 短时原型可复刻的抽象机制（自行设计素材/规则） |
|---|---|---|
| 《开蚌直播间》互动游戏金奖 | 点击/收集/稀有掉落，重复游玩，作品作者持续听取玩家反馈 | 30秒一轮：选择一个贝壳→展示结果→收集图鉴→分享卡片；使用少量可解释的随机结果，先打通循环再加装饰 |
| 《拓扑五子棋》人文知识金奖，[公开代码](https://github.com/YinkaiYu/topology-gomoku) | 规则熟悉、空间新奇；七关递进，边界教程与棋局直接结合 | 仅做一个“左右相接的圆柱棋盘”或单一跨界规则；用演示动画/关卡引导玩家自己发现规律。不要尝试短赛复刻完整七种曲面和三维系统 |
| 《Kore自介生成器》人气大奖 | 表单统一输入→应用到画布→自定义模板，手机编辑更易用；作者根据反馈修复字数限制等问题 | 选一个常见社交模板，只做结构化字段、实时预览、保存/导出；验证字数错误和窄屏输入，不必先加AI |
| 《剪纸生花》数字艺术金奖 | 少量操作生成可分享的剪纸图形 | 用对称/旋转/重复规则生成一张SVG/Canvas作品，提供撤销、重置、导出；代码生成视觉而非依赖大量外部素材 |

### 对本赛事更可靠的实现顺序

1. 先挑一个两分钟能讲清的使用场景和一条完整交互循环；作品不必“必须用视觉/必须用Agent”。
2. 用确定性本地逻辑完成玩法、工具或知识体验；留出状态、结果和可展示反馈。
3. 只有当AI增加了明确用户价值时再调用：可在回合结算生成总结、解释或下一轮内容；受限结构化输出并提供静态回退。
4. 让同学实际试玩，观察首屏是否理解、操作是否成功、是否愿意重开；把一个高频问题修好，比未验证地添加新功能更有价值。
5. 评分和用户人气分开考虑：小红书官方比赛赛道奖看价值、完成度/体验、创意独特性；人气奖按有效点赞。当前训练营评分不同，不能照搬平台赛机制。
