# 素材资源与许可核查

短赛最省时间的美术策略通常是少用素材、统一风格、自己生成简单形状；外部素材只在授权清楚且确实提升表达时加入。

## 1. 可查找的资源库

| 来源 | 适合 | 许可/使用要点 |
|---|---|---|
| [Kenney Assets](https://kenney.nl/assets) / [许可FAQ](https://kenney.nl/support) | 2D角色、UI、图标、音效、低多边形资源 | 官方说明素材包使用CC0，可商用、不要求署名；下载后仍保留压缩包里的license/readme，记录具体包名和页面链接 |
| [The Met Open Access](https://www.metmuseum.org/zh/hubs/open-access) | 文化、美术、艺术品图片/基础信息 | 官方案例约492,000张公共领域图像和数据；必须逐件确认藏品页面明确标为Public Domain/Open Access，记录作者、作品名、对象URL和权利状态 |
| [OpenGameArt](https://opengameart.org/) / [FAQ](https://opengameart.org/content/faq) | 像素图、Tileset、背景、音效、音乐 | 平台说明允许按素材授权使用；每个条目的CC0、CC-BY、CC-BY-SA、GPL等要求不同。作者常在页面标注credits要求；不可只看站点“免费”字样 |
| [Freesound](https://freesound.org/) / [许可FAQ](https://freesound.org/help/faq/#licenses) | 环境声、短音效、采样 | 每条音频由作者选CC0、CC-BY或CC-BY-NC等；商业/公开传播、署名及修改条件不同；逐条看license和作者信息，记录原始链接 |
| [p5.js](https://p5js.org/) | 用代码生成图案、粒子、互动图形 | p5.js库本身GNU LGPL v2.1；生成的图形/第三方贴图许可需单独确认 |
| [Phaser Labs](https://labs.phaser.io/) | 查2D玩法、碰撞、摄像机、输入和动画示例 | Examples仓库说明代码MIT，但其中素材不一定许可在游戏中复用；只看机制也很有价值 |

## 2. 无外部美术素材也能完成的做法

- Canvas绘制圆、线、遮罩、粒子、轨迹和碰撞反馈；CSS做渐变、卡片和弹性动画。
- SVG画简洁图标和纹样；用系统字体、Emoji或Unicode做占位元素。
- Web Audio API合成点击、命中、失败提示音；音效仍要检查对外输出/素材来源。
- 选定一套调色板和两种字号，避免各模块视觉风格不一致。
- 先确保低保真流程完整，再按剩余时间替换素材；每个引用素材写进`THIRD_PARTY_NOTICES.md`。

## 3. 许可记录表

每个外部资源一行，代码/模型/声音/图像分开记录：

| 字段 | 记录内容 |
|---|---|
| 名称 | 素材或代码包名称 |
| 原始URL | 具体项目/素材单页，不只写聚合平台首页 |
| 作者/来源 | 作者、机构或数据库 |
| 类型 | 代码、模型、图像、音频、字体、数据 |
| 许可证 | MIT、Apache-2.0、CC0、CC-BY、CC-BY-SA、CC-BY-NC等；不清楚就写“未确认” |
| 需要的署名/附带文件 | 完整署名文本、license文件、notice文件、变更说明 |
| 用在哪里 | 文件路径、页面、音效或模型用途 |
| 核验时间 | 日期；之后复查素材页和赛事规定 |

## 4. 不要踩的坑

- 模型权重、训练数据和源码可能是不同许可证；网页Demo能运行不等于允许下载/再分发。
- 预览图与下载文件、素材包内二次素材可能许可不同；只记录预览截图不够。
- CC-BY要署名；CC-BY-SA有相同方式共享条件；CC-BY-NC不适合商用；逐项阅读具体条款。
- 生成式AI产物也要确认输入素材、平台输出条款及赛事要求；不将秘密/个人数据送入外部模型。
- 比赛交付若包含演示视频、直播或公开仓库，注意图像、音乐、字体和肖像的传播授权范围。
