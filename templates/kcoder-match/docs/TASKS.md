# 任务板

状态：赛前空模板；无任务已派发，无任务已完成。仅对实际开工任务编号。

## 单任务格式（复制此块，不把所有字段重发到每轮对话）
- ID / 负责人 / 阶段 / 状态：
- 目标（一个可验收结果）/ 为何现在做：
- 允许文件 / 独占修改文件 / 禁止范围：
- 输入、接口 / 前置任务：
- 验收行为 / 适用命令 / 必须手动验证项：
- 时间盒 / 预算软上限 / 停止条件：
- 结果：变更路径、命令与退出码、人工结果、未验证/阻塞。
- 用量：开始/结束计数、平台范围ID、时间、口径；未取得则写未取得。

## 建议的工作包（尚未创建为已批准任务）

| 顺序 | 工作包 | 通过条件 |
|---|---|---|
| 0 | 现场事实与加载探针 | AGENTS加载可核对，项目路径、模型、计量、远程链路已确认 |
| 1 | 一个差异交互的风险探针 | 真实设备最小输入→事件有效；创新机制可以单独试用，失败及时缩减 |
| 2 | 单局端到端 | 开始→操作→反馈→结束→再玩，核心路径有确定性测试 |
| 3 | 识别与回退、素材整合 | 真实输入与回退分别验收，权限异常可见，资产来源清晰 |
| 4 | 回归与交付 | 核心用例/构建有真实结果，四件套齐备，已知限制明确 |

夜间只批准上述已分解、输入接口稳定的具体任务。每项都要有负责人、路径、验收和停止点；涉及同一核心文件的工作串行。
任务完成率：使用开工时确认的验收单元，报告完成/总数，另列失败、阻塞、取消、拆分变更；这是内部观察，不冒充官方计算公式。
