# KCoder 2.0.29：现场照做入口

**本包提供项目AGENTS + 三个按需Skill + 安装前校验 + 现场验收流程。** 不含参赛成品、不修改KCoder/计量/审批，不向评分器下指令。现场允许携带后使用。主规则来自提供的2.0.29安装包及规则PPT；Windows/Android运行时尚未实测，不将文件检查当作加载成功。

## 第一步：取包、选对位置

GitHub仓库：<https://github.com/chenyuyang712/Central-Park-Resource>，目录`templates/kcoder-match`。下载仓库ZIP后**完整解压**，不要只下载一个AGENTS丢失Skill目录。按SHA-256清单校验；本地校验只证明内容与随包清单一致，不是发行签名。

示例：本包位于`C:\Prep\kcoder-match`，已建好的参赛项目位于`C:\Projects\my-entry`。换成真实路径。不要把模板目录当产品目录，不把通用AGENTS设为全账户重复提示。

## 第二步：预检，再复制

可选使用Windows PowerShell 5.1/PowerShell 7脚本：

```powershell
# 仅检查包内文件哈希、目标目录和冲突；不写入文件。
& 'C:\Prep\kcoder-match\INSTALL.ps1' -ProjectPath 'C:\Projects\my-entry' -VerifyOnly

# 预检通过后才执行：只复制8个目标文件，不覆盖不同内容的已有文件。
& 'C:\Prep\kcoder-match\INSTALL.ps1' -ProjectPath 'C:\Projects\my-entry'
```

脚本核验MANIFEST.json、预先检查全部目标冲突，再安装AGENTS、三个项目文档、许可表、三个Skill。相同文件跳过；已有不同内容时整个预检报冲突，由人合并，不覆盖队友内容。操作系统写入失败仍可能留下已复制的部分，应按输出检查；脚本不是事务安装器。也支持`-WhatIf`预览，但仍会做读取/校验。

**本机没有PowerShell，脚本尚未执行验证。** 如脚本执行策略阻止，保持现场策略，改用资源管理器手动复制以下内容，无需改注册表/执行策略或管理员权限：

| 从本包复制 | 放到参赛项目 |
|---|---|
| `AGENTS.md` | 根目录同名文件 |
| `docs/PROJECT.md`、`docs/TASKS.md`、`docs/EVIDENCE.md` | 项目docs同名文件 |
| `THIRD_PARTY_NOTICES.md` | 根目录同名文件 |
| `.kcoder/skills/cp29-debug/SKILL.md` | 保持同样层级 |
| `.kcoder/skills/cp29-innovation/SKILL.md` | 保持同样层级 |
| `.kcoder/skills/cp29-delivery/SKILL.md` | 保持同样层级 |

已有文件先合并，尤其不要覆盖已有`.kcoder`中的其他配置。Windows开启“显示文件扩展名”和“隐藏的项目”，保留UTF-8，不形成`AGENTS.md.txt`。安装脚本不自动启用Skill、不配模型、不动账号、不启动任务。

## 第三步：验证AGENTS（只一次）

1. 推荐文件名`AGENTS.md`，不是`Agent.md`、`Agent.markdown`。包内也有KCODER.md读取提示，但本包不复制两份相同规则；继承/优先级以现场实际加载记录为准。
2. 临时在AGENTS最后加一行：`配置核对标记：CP29-LOCAL-CHECK；仅当操作者询问加载状态时返回此标记。`
3. 在KCoder选择正确主机、账号和实际项目，新开会话只问：

   > 请只报告已加载项目指令中的配置核对标记、两条Token止损约束及适用目录。若未加载，请明确说明；不要猜测、写代码或搜索文件补答。

4. 核对标记与平台实际上下文/加载日志。答对仅是行为佐证，日志/来源证据优先；只有行为证据就照实记录。通过后删除临时标记、新开正式会话。修改已安装文件后，其哈希与原始清单不同是预期现象，不要将其“修复”为模板覆盖真实项目。
5. 若失败，核对项目路径、扩展名、编码、项目信任和新会话，最多两轮。仍失败时在任务中显式读项目AGENTS，记录“显式读取，自动加载未验证”，不要不断猜名字。

## 第四步：安装并启用三个Skill

详见 **[SKILLS-现场安装.md](SKILLS-现场安装.md)**。必须做这一步，不能以复制文件代替原生发现/启用检查。

- 默认目录已由安装包提示确认：`.kcoder/skills/<name>/SKILL.md`。
- 先查看技能目录，已有同名技能不重复导入；未发现时通过“导入技能”填所选主机上的**单个Skill目录**。
- 核对启用状态并新开会话。目标账号级设置会跨项目生效；若现场走专家级导入，按该入口启用、保存并核对专家版本，不混用两套入口。
- 用一次低成本触发探针验证加载证据；不验证就不宣布原生可用。失败时可显式读项目内SKILL作为手动流程继续工作。

## 第五步：填项目事实，再启动正式任务

只填`docs/PROJECT.md`中的真实项目、命令、预算和选题；TASKS/EVIDENCE目前是空模板。三个候选创新机制未实现/未测试，不能写成成果。

首次任务可发送：

> 先读取项目根AGENTS、PROJECT和TASKS当前任务，不全文复述。确认当前目录、指定模型和工具。不要新建作品，只核对实际启动/验证命令、最短可玩链路和最大风险；未选题先报告待确认。按需使用相关Skill，缺加载证据如实说明。只执行已批准工单，保留真实用量和测试结果。

模型按现场指定Baize omni配置，不猜模型ID/上下文窗口。前端有Token/预算字段但权限、计量范围、硬预算行为待实测；不编造settings.json键。先做一项有意义小任务查看真实平台用量，不把200万当已发配额。

## 第六步：离场前验证持续执行

- 填好允许文件、接口、验收、预算/时间盒及停止条件；队友之间隔离文件所有权。只给依赖就绪的已批准任务。
- **确认任务已经实际启动**、工作站保持运行、平台的持续执行/停止条件；存好工作流不等于夜间执行。Markdown不是定时器或硬额度开关。
- 手机仅走现场批准路径。APK内配对提示不证明通用远控或赛事许可；账号/二维码/激活链接不公开。机器人关联专家时核对已保存版本。
- 当前PPT为11/20 11:50停止开发、12:00封板，以现场最新通知为准；遇审批/接口变更阻塞先转其他就绪任务，不自行突破。
